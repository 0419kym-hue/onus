# ON:US 보안 점검 결과

> 점검일: 2026-11-06 · 점검 방법과 결과를 그대로 적었습니다. 확인하지 못한 것은 "미확인"으로 표시합니다.

## 1. 제출 요건 점검

| 항목 | 결과 | 확인 방법 |
|---|---|---|
| GitHub 저장소 공개(Public) | 통과 | GitHub API `private: false`, `visibility: public` (https://github.com/0419kym-hue/onus) |
| 비밀 파일·API 키가 저장소에 없음 | 통과 | 전체 커밋 기록과 현재 작업 폴더에서 OpenAI 키(`sk-`), Vercel 토큰(`vcp_`), GitHub 토큰, Supabase 비밀 키, 서비스 롤 키 형태를 검색 → 발견 0건. 추적되는 `.env*`는 `.env.example`(이름만, 값 없음) 하나 |
| `.env.local`·`.vercel` 제외 | 통과 | `.gitignore`의 `.env*`, `.vercel/` 규칙, `git check-ignore`로 확인. GitHub raw 주소로 요청하면 404 |
| 결과물 주소가 누구나 열림 | 통과 | 짧은 주소 `https://hy-company-eight.vercel.app/onus` 가 로그인 없이 200으로 응답 |
| Vercel Authentication(배포 보호) 꺼짐 | 통과 | Vercel API로 프로젝트 설정 조회: `ssoProtection: null` (보호 없음) |
| localhost·관리 화면·임시 긴 주소가 아님 | 통과 | 제출 주소는 프로젝트 별칭(짧은 주소)이며 `vercel.com/…`·`-git-…`·해시가 붙은 주소가 아님 |

## 2. 코드·설정 점검

| 항목 | 결과 | 내용 |
|---|---|---|
| 서버/브라우저 키 분리 | 통과 | `OPENAI_API_KEY`는 서버 API route(`app/api/onus/recommend/route.ts`)에서만 읽음. `NEXT_PUBLIC_` 접두사가 붙은 값은 Supabase 공개 URL·공개(publishable) 키와 지원 폼 주소뿐 |
| 서비스 롤 키 | 통과 | 저장소·브라우저 코드에 없음(`SUPABASE_SERVICE_ROLE_KEY`는 서버 환경변수로만 사용) |
| 운영 의존성 취약점 | 통과 | `npm audit --omit=dev` → 0건. (개발 도구인 Supabase·Vercel CLI 쪽에는 별도 경고가 있으나 배포 결과물에 포함되지 않음) |
| 보안 응답 헤더 | 적용 | `next.config.ts`: `X-Content-Type-Options: nosniff`, `X-Frame-Options: DENY`, `Referrer-Policy`, `Permissions-Policy`, `Content-Security-Policy(frame-ancestors 'none'; base-uri 'self'; object-src 'none'; form-action 'self')`, `X-Powered-By` 제거 |
| AI API 보호 | 적용 | 같은 출처 요청만 허용, IP당 분당 5회, 본문 5,000자 제한, 후보 번호 검증(AI가 만든 제목·링크를 쓰지 않음), 오류 내용은 서버 로그에만 기록, `ONUS_AI_DISABLED`로 끄기 가능 |
| 입력 저장 | 통과 | AI 추천·장학금 자가 진단의 입력은 서버에 저장하지 않음. 이름·학번·연락처를 받지 않음 |
| DB 접근 제어 | 적용 | Supabase RLS + 컬럼 단위 권한: 공개 컬럼만 읽힘, 삭제 비밀 키(`edit_key`)는 읽을 수 없음(직접 요청해 401 확인), 잘못된 키로 삭제 시도는 거부, 운영자 전용 함수는 일반 사용자에게 거부 |
| 업로드 | 적용 | 파일 형식(이미지·PDF)·크기(5MB) 제한, 분당 업로드 수 제한, 증빙 서류는 비공개 저장소에 두고 승인·반려 후 삭제 |

## 3. 남아 있는 한계 (숨기지 않고 공개)
- `script-src`를 제한하는 CSP는 적용하지 않았습니다. Next.js의 인라인 스크립트 때문에 nonce 구성이 필요해서이며, 현재는 iframe 삽입·플러그인·외부 base 악용만 막습니다.
- 익명 글쓰기는 분당 30건 제한(DB 트리거)만 있어 대규모 스팸에는 약합니다.
- Supabase 공개(publishable) 키는 브라우저에 내려가도록 설계된 키이며 비밀이 아닙니다. 권한은 RLS로 제한됩니다.
- `/onus/submit`(수상작 올리기)는 DB 마이그레이션이 적용되기 전까지 열리지 않습니다. 적용 전에는 저장 동작을 확인하지 못했습니다.
- OpenAI 사용량 한도는 OpenAI 대시보드에서 설정해야 하며 코드로 제한하지 않았습니다.

## 4. 다시 점검하는 방법
```sh
git ls-files | grep -i "\.env"                 # .env.example 외에 나오면 안 됨
npm audit --omit=dev                            # 운영 의존성 취약점
curl -sI https://hy-company-eight.vercel.app/onus   # 보안 헤더와 200 응답 확인
```
