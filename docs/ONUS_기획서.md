# ON:US 최종 기획서 및 개발 계획

한양여자대학교 AI 해커톤 **트랙 2 (AI 기술 미사용)** · 공모전·대회 경험 공유 및 인증 리뷰 플랫폼
표기: **[확인]** 실제로 확인한 사실 · **[가설]** 아직 검증하지 않은 가정 · **[결정]** 대화에서 합의한 내용 · **[제안]** 이 문서에서 새로 제안, 확인 필요

---

## Context (왜 만드는가)

공모전 정보, 과거 출품작, 수상 경험, 준비 과정, 실제 피드백이 개인과 학과에 흩어져 있어서 후배가 새 대회에 도전할 때 선배 경험을 활용하기 어려울 수 있다. **[가설]** 실제 공유 수준이 낮다는 주장은 검증 전이며, 학교 공식 자료와 인터뷰로 확인한다. 확인된 것은 다음뿐이다.

- **[확인]** 한양여대는 공모전 수상을 보도한다(전시디자인공모전 대상 등). 학교가 AI 활용 수상 경험을 숏폼으로 공개한 사례도 있다.
- **[확인]** 씽굿, 위비티, 링커리어 등은 정보·수상작·인터뷰를 제공한다. 씽굿 인터뷰 2건은 주최사 인터뷰였고 본문은 이미지라 읽지 못했다. 갤러리 1건에는 제작 과정, 심사평, 규격이 없었다.
- **[확인]** 한양여대 학생 대상 설문이나 연구는 찾지 못했다. **사용자 검증 결과는 아직 없다.**

ON:US는 학교 구성원 중심으로 **선배의 실제 출품작·준비 과정·규격을 공모전 회차와 연결**하고, **인증된 경험자에게 익명 피드백을 요청**하게 한다. 트랙 2이므로 **AI 기술은 사용하지 않는다.** 연결과 정리는 모두 규칙 기반으로 처리한다.

**한 문장 정의 [결정]:** 공모전을 찾아보는 한양여대 학생이 선배들의 실제 출품작·수상 경험·준비 과정·제출 규격을 근거로 자신의 새로운 도전을 준비하고 발전시키게 한다.

# PART A. 기획서

## A1. 문제와 핵심 사용자
- 중심 문제 **[가설]**: 내 작품이 이 대회에서 통할지 판단할 기준과 참조점이 없다. 원인은 수상 기준과 제작 판단이 암묵지로 남고, 결과물만 공개되며, 경험 정리에 동기가 없다는 점이다.
- 제외한 문제: 공모전 목록 탐색(기존 서비스가 해결). 확장 영역: 필기, 팀 모집 등.
- 핵심 사용자 **[결정]**: 같은 학과에서 이번 학기 공모전을 실제로 준비하거나 찾아보는 학생. 공급자(수상·참가 선배)는 첫 만족 대상이 아니라 소수를 직접 확보할 파트너.
- 대상 범위 **[결정]**: 한양여대 재학생·졸업생. 해커톤에서는 1개 공모전 유형으로 좁혀 시연.
- 가장 큰 위험 **[가설]**: 후배는 사례가 있어야 오고, 사례는 선배 참여가 있어야 생기는 순환. 선배가 실제로 요청을 수락하는지는 미검증.

## A2. 기존 서비스와의 차별성
- 이미 있는 것: 공모전 검색, 수상작 갤러리, 수상자·주최사 인터뷰, 일반 AI 피드백, 포트폴리오 공개, 멘토링.
- 주장하지 않는 것: 인터뷰·갤러리 자체, 수상 팁 일반론, AI 작품 평가.
- 차별점 **[결정]**: 공모전 회차 → 규격 → 선배 작품·과정 → 인증 경험자의 익명 리뷰가 **하나의 구조로 연결**되고, 학교 구성원 안에서 축적된다. 경쟁력의 핵심은 기술이 아니라 **같은 학교 경험자의 과정 데이터와 신뢰**이다.

## A3. 핵심 가치와 기술 방침 (AI 미사용)
- 학생 행동 변화: 막연히 찾아보던 학생이 선배의 실제 경험과 인증 경험자의 피드백을 근거로 다음 행동을 정한다.
- **AI 기술은 사용하지 않는다 [결정: 트랙 2]**. 아래는 모두 규칙 기반이며 화면·발표 어디에서도 AI라고 표현하지 않는다.
  1. 요강 → 제출 규격·참가 조건: 운영자가 입력 양식으로 직접 구조화하고 공식 요강 원문 링크를 병기
  2. 증빙 문서: 운영자가 원본을 눈으로 확인하고 문서 종류·대회명·연도·수상 등급을 직접 선택·입력
  3. 수정 체크리스트: 리뷰어가 고른 개선 분류(구성/규격/표현/주제/제작)와 개선점 문장을 학생 화면에서 체크리스트로 정리. 여러 리뷰어가 같은 분류를 고르면 '공통 개선 요소'로 표시. **새 문장을 만들지 않고 리뷰어가 쓴 문장 그대로** 보여 준다.
- **그 밖의 규칙 기반 기능 [제안]**: 리뷰어 후보 추천(유형·분야·대회 일치도 점수와 추천 이유 표시), 공모전·작품 추천(학과·관심분야 필터와 마감순), PDF 규격 점검(페이지 수, 용지 크기, 파일 형식, 용량).
- **하지 않는 것 [결정]**: 작품 점수화, 수상 가능성 예측, 가짜 리뷰어·가짜 리뷰 생성. 규격 점검 결과에는 "확인됨 / 미충족 / 확인 필요"를 함께 표시.

## A4. 리뷰어와 인증 체계 [결정]
- 자격: 수상 경험 인증 / 출품 경험 인증 / 전공 선배 인증 / 일반 재학생. **한 사람이 여러 자격 보유 가능**(배지 테이블에 여러 행).
- **출품신청서만으로는 참가 경험 불인정.** 접수 완료 기록 또는 공식 결과 자료 필요.
- 흐름: 증빙 업로드 → 운영자가 원본 확인 후 정보 직접 입력 → 승인 시 배지 부여. 증빙 원본과 실명은 학생에게 공개하지 않는다.
- 학생에게 보이는 것: 익명 코드, 확인된 경험 유형, 관련 분야, "학교 구성원 경험자(공식 심사위원 아님)" 고지.
- 공개 범위 **[제안]**: 대회명·연도·수상 등급 각각을 리뷰어가 선택, **기본값은 모두 비공개**. 매칭은 내부 정보(같은 대회, 같은 분야)로 하고 표시 정보와 분리. 같은 유형 풀이 3명 미만이면 "경험자가 적어 신원이 추정될 수 있어요" 안내를 표시한다(차단하지 않음).
- 리뷰어가 수락해야만 작품 열람 가능. 리뷰어 열람은 다운로드 없이 서버가 발급하는 기한 있는 링크로 제한.

## A6. 검증 계획 (이번에는 실제 인터뷰를 하지 않았으므로 결과는 아직 없음)
- 목표 **[결정]**: 후배·처음 준비하는 학생 3명 정도, 참가·수상 선배 2명 정도. 팀원·친구 제외는 확보되는 만큼만, **실제 확보한 인원만 결과에 반영**하고 부족하면 한계로 명시. 전체 2~3시간 배정.
- 단계 1(짧은 인터뷰, 과거 행동 중심)과 단계 2(컨시어지: 학생의 실제 질문 1개를 선배에게 익명 전달해 응답 확인)는 우선 진행. 단계 3(프로토타입 과업 1개)은 시간이 허용될 때만.
- **주 지표**: 테스트 직후 학생이 쓴 "이번 주에 할 행동" 중 구체적이고 근거 있는 행동. **평가표(각 0~2점)**: 구체성(동사+대상+기한/조건), 근거의 명확성(어떤 자료·피드백에서 나왔는지), 실행 가능성. 평가자 2명이 작성자·방법(기존/ON:US)을 가린 채 독립 채점, 2명 확보 불가 시 가능한 인원으로 진행하고 한계 표시.
- **보조 지표(4개)**: 규격 찾기 정확도·시간, 과제 완료·막힘 지점, 공급 응답(컨시어지 응답 여부·시간, 공개 가능 항목), 커버리지(학생이 실제 준비하는 공모전이 우리 자료에 있는지).
- **인증 라벨 테스트 [결정]**: 같은 피드백을 "일반 재학생"과 "수상 경력 확인"으로 달리 표시해 신뢰도와 **신뢰한 근거를 먼저 묻는다**. 참가자는 한 버전만 본다. 라벨의 영향과 내용 자체의 가치를 구분해 기록. 시간이 부족하면 부가 항목으로 미룬다.
- **임시 판정 기준 [결정]** (5명 기준): 4명 이상이 관련 정보를 찾아 검증 리뷰어 요청을 완료하거나 기존보다 구체적 행동을 도출 → 긍정적 초기 신호 / 2~3명 → 추가 검증 필요 / 1명 이하 → 문제 정의·UX 재검토. 인원이 5명이 아니면 비율로 환산하지 않고 "N명 중 M명"으로만 쓴다. **통계적으로 효과가 입증됐다는 뜻이 아니라 해커톤용 임시 기준**이다.
- 가설이 틀렸을 때 방향 전환은 이전 논의 표(수요/열람/피드백/공급/반익명별)를 따른다.
